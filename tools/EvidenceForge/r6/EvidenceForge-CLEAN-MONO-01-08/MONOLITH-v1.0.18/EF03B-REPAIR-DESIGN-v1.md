# EF-03B REPAIR DESIGN v1 — MONOLITH-v1.0.10

**Définition :** `v1.0.10 = v1.0.9 + EF-03B REVIEW RESILIENCE` — et rien d'autre. Base : `EF03B-REAL-RUN-AUTOPSY-v1.md`, `EF03B-FAILURE-TAXONOMY-v1.md`, `EF03B-COST-ANALYSIS-v1.md`. Principe : **ne jamais relâcher le contrat scientifique pour faire passer une revue** — le prompt EF-03B gelé (MONO-01), le validateur local à schéma fermé et les stratégies de reprise (MONO-11 v0.3-r1, gelé) et le parseur EF-03B gelé restent les seules autorités ; le lot gelé n'est pas modifié.

## 1. Architecture : un adaptateur additif autour de `llmCall`

`lib/ef03b-resilience.js › createReviewAdapter({ llm, runDir, runId, attemptId, sealHash, config })` est branché dans `lib/pipeline.js` sur l'objet `llm` remis à `runDownstreamFromCheckpoint` (inchangé, byte-identique à v1.0.9) : `{ ...llm, llmCall: adapter.llmCall, onValidation: adapter.onValidation }`. Le lot gelé continue d'appeler `llmCall(prompt, meta)` à chaque passe et de valider ce qui revient. L'adaptateur n'agit que sur ce qui **entre** (prompt + `max_tokens`) et **sort** (texte candidat) du transport ; il ne touche ni au prompt gelé (il y *ajoute* un contrat de forme), ni au validateur, ni au nombre de passes, ni au fail-closed. Tout appel LLM passe par `llm.llmCall` réel (garde-budget, verrou de transport, ledger, streaming, journal, statut live).

Ordre de préférence appliqué : **1. prévenir** (budget de sortie, `max_tokens` dimensionné, citations sur une ligne copiées octet pour octet) → **2. réparer localement si purement structurel et déterministe** (framing JSON après troncature ; fusion déterministe) → **3. retry ciblé** (complétion des seules dimensions manquantes ; littéralisation sur extraits des seules citations fautives ; puis la réparation ciblée gelée) → **4. régénération complète en dernier recours** (reprise informée gelée, inchangée).

## 2. Mesures

| Mesure | Détail | Ce qui ne change pas |
|---|---|---|
| **E. Registre des revues VALID** (`reviews-valid.jsonl`) | Clé = `sha256(prompt EF-03B de passe 1)` — le prompt gelé encode jumeau, preuves (`worksUsed`), document, schéma — + sceau MONO-11 + contrat `MONO-11-v2`. Écrit dès `onValidation(valid)` (avant tout checkpoint) : un run interrompu ne reperd plus ses revues. | **A. Contrat de budget de sortie** | Préambule ajouté au prompt de passe 1 (et aux reprises informées) : `finding` ≤ 600 car., `rationale` ≤ 600, `limitations` ≤ 2 × 200, 1–3 citations ≤ 200 car. **sur une seule ligne, copiées octet pour octet, marqueurs Markdown inclus, jamais d'items joints** ; interdits : résumé du dossier, répétition, citations longues, justification dupliquée, prose hors JSON. | Aucune exigence scientifique retirée ; 10 findings, mêmes champs, mêmes règles. |

Justification : réponses complètes observées 6,2–8,2 k jetons ; 12 288 ≥ 1,5 × la médiane ; coût de sortie engagé seulement s'il est produit. | Preflight, couverture, agrégation : 8192 inchangé. |

| **B/G. Littéralisation sur extraits** | Si les seules erreurs restantes sont `TARGET_REF_NOT_LITERAL` : classification déterministe de chaque citation rejetée (`classifyNonLiteralRef` : espaces / sauts de ligne, marqueurs Markdown, items de liste joints, cases à cocher, partielle, paraphrase) et localisation du **span exact** du document (normalisation indexée, réversible). **Une** reprise ciblée sur **extraits** (± 300 car. autour de chaque span, pas le document entier : ≈ 3 k jetons au lieu de 45 k) propose le span ; le modèle **choisit** (span, autre passage contigu, ou `[]`) ; recomposition par `recompose` (fonction gelée) ; re-validation. Le prompt porte l'empreinte de contexte déterministe (`repairContext` gelé) : jamais réutilisable pour un autre constat. | **Jamais une citation réparée localement** (T-EF03B-14) ; sans span exact (paraphrase) ⇒ réparation ciblée gelée inchangée. |
| **Réparation locale (C)** | Uniquement : framing JSON des findings complets après troncature ; fusion ; wrapper Markdown déjà géré par `extractJson` gelé. | Sens, conclusion, citation, preuve, disposition, statut épistémique : **jamais**. |

## 3. Frontières documentées (aucune modification du lot gelé)

- Le MONOLITH compose désormais **deux prompts propres** (complétion = prompt gelé + trailer ; littéralisation = extraits) : c'est la frontière explicite v1.0.10, consignée dans le test V4 (qui interdit toujours d'appeler les constructeurs gelés et exige l'empreinte de contexte).
- **Non fait, car il faudrait toucher MONO-11** : réutiliser une passe 1 de couverture *invalide* pour ne rejouer que la reprise informée (cause de la non-stabilité des jumeaux entre tentatives : 3/17 jumeaux changent de preuves, ce qui invalide légitimement le reuse de leur revue) ; laisser le lot gelé consommer un `stop_reason`. Ces points relèvent d'une version candidate MONO-11 et d'une décision de gouvernance.
- La couverture EF-02D3 rejouée à chaque reprise (≈ 0,6 USD) n'est pas traitée ici (hors « EF-03B REVIEW RESILIENCE et rien d'autre »).

## 4. Coût attendu (unités mesurées ; réussite non inventée)

Passe 1 complète 0,265 USD (avec budget de sortie, attendue plus courte) ; complétion 0,149 ; littéralisation ≈ 0,02 ; régénération complète 0,267. Une revue tronquée coûte au pire 0,265 + 0,149 + 0,02 = 0,43 USD **à la passe 1** au lieu de 0,27 × 3 = 0,81 USD pour 3 troncatures successives (5 revues du run réel). Une revue VALID réutilisée : 0. Voir `EF03B-REPLAY-v1.md` (SIMULATED / EXPECTED_NOT_YET_PROVEN).
