# D103P0.1 — Grille de revue professionnelle de structure

## Je marche comme je suis

**Version :** v0.2  
**Statut :** grille de revue professionnelle à compléter  
**Entrée requise :** D103P0.0-B — Analyse descriptive comparative S01 / S02 v0.3  
**Étape suivante autorisée après revue :** D103P0.2 — Taxonomie minimale  
**Interdit à ce stade :** taxonomie définitive, règles métier, seuils, profils-types, prescription, bibliothèque d’exercices, logique de décision codée.

---

# 1. Objet

Cette grille sert à réaliser **D103P0.1 — revue professionnelle de structure** à partir des deux cas sentinelles S01 et S02.

Elle ne demande pas au relecteur de proposer un programme d’activité, de juger les personnes, d’établir un diagnostic ou de concevoir le futur moteur.

La question centrale est :

> **Qu’est-ce que la structure doit savoir représenter pour pouvoir accueillir correctement ces deux personnes, sans connaître à l’avance qui elles sont ?**

---

# 2. Principe anti-hardcoding

S01 et S02 restent deux répondants candides et interchangeables.

```text
S01 / S02
= cas d’observation
≠ profils produit
≠ règles métier
≠ catégories
≠ seuils
≠ exceptions codées
```

Aucune valeur, préférence, difficulté, activité, formulation, combinaison ou chiffre propre à S01 ou S02 ne doit devenir directement :

- une branche de code ;
- un seuil ;
- une catégorie ;
- un profil ;
- une règle de progression ;
- une règle de suitability ;
- un libellé produit ;
- une recommandation automatique.

La revue doit faire émerger uniquement des **besoins génériques de représentation**, formulés indépendamment de la personne qui les a révélés.

---

# 3. Position du relecteur

Le relecteur examine :

- la qualité de la structure de recueil ;
- ce qu’elle permet de comprendre ;
- ce qu’elle ne permet pas de comprendre ;
- les ambiguïtés qu’elle génère ;
- les données qui semblent nécessaires ou inutiles ;
- les risques d’interprétation abusive ;
- la séparation entre faits, déclarations, contexte, objectif, expérience réelle et récupération.

Le relecteur ne doit pas :

- diagnostiquer S01 ou S02 ;
- proposer un traitement ;
- transformer un antécédent en règle ;
- inférer une capacité non déclarée ;
- supposer qu’une donnée vide signifie « non » ;
- généraliser à une population ;
- construire P0.2 à la place de P0.1.

# 5. Grille de décision

Pour chaque point examiné, utiliser si possible l’un des statuts suivants :

- **CONSERVER** — la structure actuelle paraît suffisante ;
- **MODIFIER** — le besoin est pertinent mais la formulation / structure est insuffisante ;
- **AJOUTER** — une information nécessaire n’est pas correctement représentée ;
- **SUPPRIMER** — l’élément paraît inutile, redondant ou trop orientant ;
- **CLARIFIER** — le sens ou la temporalité est ambigu ;
- **À REVOIR** — impossible de conclure à ce stade.

Toute décision doit être justifiée.

# 34. Critère de clôture de P0.1

P0.1 est terminé seulement si :

- les exports bruts S01/S02 ont été relus ;
- P0.0-B a été relu ;
- les ambiguïtés ont été examinées ;
- les inconnues ont été préservées ;
- les aides facultatives ont été examinées pour leur potentiel d’orientation ;
- les besoins génériques de représentation sont explicités ;
- aucune règle métier n’a été produite ;
- aucun seuil n’a été produit ;
- aucun profil utilisateur n’a été produit ;
- aucune activité propre à un cas n’a été transformée en catégorie obligatoire ;
- les réserves professionnelles sont documentées ;
- un verdict explicite autorise ou non le passage à P0.2.

# 35. Transition autorisée

Si le verdict de P0.1 autorise la suite :

```text
S01 + S02
+
P0.0-B
+
revue professionnelle P0.1
+
besoins génériques confirmés
→ D103P0.2 — taxonomie minimale
```

P0.2 devra rester minimal et chaque dimension proposée devra pouvoir être reliée à un besoin de représentation confirmé pendant P0.1.

**Aucune dimension ne doit être introduite uniquement parce qu’elle semble intuitivement intéressante.**
